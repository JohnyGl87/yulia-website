## איך הטופס עובד — בלי שירות צד ג'

אתר סטטי לא יכול לשלוח מייל בעצמו, ובכוונה לא השתמשנו בשום שירות חיצוני.
במקום זה: המבקר ממלא את הטופס, ובלחיצה על "שליחה בוואטסאפ" (או "שליחה במייל")
נפתחת אצלו האפליקציה שלו עם ההודעה **כבר מוכנה בפנים**, והוא רק לוחץ שלח.

**היתרונות:** אפס הרשמות, אפס עלות, אפס תלות בגורם חיצוני, ואף פרט אישי לא
נשמר בשום שרת. בישראל וואטסאפ גם ממיר טוב יותר מטופס רגיל.

**החיסרון:** הפנייה נשלחת מהחשבון של הפונה, כלומר הוא רואה אותה לפני השליחה
ויכול לוותר באמצע. אם בעתיד תרצו טופס ש"נשלח לבד" ישירות למייל — אפשר להוסיף
שירות חינמי כמו Web3Forms בשינוי קטן ב-`app.js`.

## תצוגה מקומית

מהתיקייה הזו, בטרמינל:

```
py -m http.server 8000
```

ואז בדפדפן: `http://localhost:8000`

השרת הזה לא מכיר כתובות נקיות, ולכן קישורים כמו `/en` או `/lecture` יחזירו בו שגיאה.
לבדיקת עמוד מסוים פותחים אותו ישירות: `http://localhost:8000/en.html`. באתר האמיתי הכול עובד.

לעצירה: `Ctrl+C`.

## פרסום (Cloudflare Pages)

האתר סטטי לגמרי — **אין שלב build**. בהגדרות פרויקט Cloudflare Pages:

- Framework preset: **None**
- Build command: **(ריק)**
- Build output directory: **`/`**

כל `git push` לענף `main` מפרסם אוטומטית תוך כדקה.

Cloudflare מגיש כתובות נקיות: `/en.html` מפנה ל-`/en`, ו-`/lecture.html` ל-`/lecture`.
הקישורים בין העמודים כתובים ישר בכתובת הנקייה (`/en`, `/lecture`, `/#about`) כדי לחסוך הפניה.

## הערות תחזוקה

- **תוכן**: כל הטקסטים יושבים ישירות ב-HTML. שינוי טקסט = עריכת המילים בקובץ.
  שינוי בעמוד עברי צריך שינוי מקביל בעמוד האנגלי המתאים.
- **צבעים וגופנים**: מרוכזים בראש `assets/style.css` בבלוק `:root`.
  עברית: Frank Ruhl Libre + Assistant. אנגלית: Cormorant Garamond + Karla.
- **הצורה החוזרת** של האתר היא העיגול — תמונות פורטרט עגולות (רכיב `.portrait`).
- **זיכרון דפדפן**: קבצי `assets/` נשמרים אצל המבקר יום אחד (`_headers`). לכן `style.css` ו-`app.js`
  מקושרים עם `?v=2`. כל שינוי באחד מהם: להעלות את המספר בכל ארבעת העמודים וב-`404.html`.
- **נתונים מובנים (JSON-LD)**: בראש כל עמוד יש בלוק `application/ld+json` שגוגל קורא. הוא חוזר על עובדות
  שכבר כתובות באתר (שם, תארים, שפות, מחיר פגישה, ההרצאה). שינוי עובדה באתר = שינוי גם שם.
- **מפת האתר**: עמוד חדש = להוסיף ל-`sitemap.xml`, ולעדכן `lastmod` כשתוכן משתנה.
